# 公演ごとの予約方式

`src/lib/site-data.ts` のLIVEデータに `reservationMode` を設定します。

- `external`: 従来の `ticketUrl` をそのまま表示。新フォームを使わない。
- `internal`: 新しい予約システムを使用。ADMINで受付期間・枚数上限・総定員・有効化を設定する。
- `none`: 予約CTAを表示しない。新フォームを使わない。
- 未指定: 新フォームには参加しない。既存の外部URLがあれば従来の外部CTAを表示する。

ECLIPSE（2026-11-07）は `external`。URLのパラメーター・文言・装飾は維持します。
TOPとLIVEの外部CTAはDBによって置き換わりません。

## 今後、新フォームを使う公演を追加する手順

1. LIVEデータへ告知内容と `reservationMode: "internal"`、固定の `eventId`（UUID）を登録する。
2. 関連NEWSがある場合は同じeventIdで関連付ける。
3. サイトへの反映後、ADMINの公演選択から受付設定を作成する。
4. 開始・締切（日本時間）、1申込上限、必要なら総定員を設定し、有効化する。

告知データは現状コード管理です。新公演の追加にはコード更新が必要ですが、フォームの再開発は不要です。
予約方式を変更する場合もコード更新が必要です。ADMINは受付設定だけを管理し、外部予約の公演を内部予約へ変更できません。

## 保護の範囲

- TOP/LIVEの外部CTAは、予約APIを使って内部CTAへ自動置換しない。
- 公開公演APIはinternal公演だけを返す。NEWSの内部予約リンクも同じ対象だけ。
- `/tickets/[eventId]` は対象外公演で404。入力フォームを描画しない。
- 予約サービスはinternal以外の申込をDBトランザクション前に拒否。
- ADMINでの受付設定作成・更新もinternalだけ許可。
- 過去に保存された外部公演の受付設定は実行時に停止扱いとなる。DBのenabledを書き換えない。
- 既存予約・メール履歴・操作履歴は削除しない。過去予約の管理用表示は保持する。

今回、DBスキーマや実DBは変更していません。
本番公開には、別途、本番専用DB・認証・メール設定と承認が必要です。
